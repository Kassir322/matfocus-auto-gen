# Аудит переносимости конфигурации

Дата аудита: 2026-07-13.

## 1. Итог

Активный v2 хранит общие настройки, секреты, локальные пути и прогресс в одном
`data/settings.json`. Файл целиком исключен из Git вместе со всем каталогом
`data/`, поэтому новый клон получает только значения из кода, а локальный файл
может незаметно переопределять обновленные значения.

Для второй подзадачи зафиксирован следующий контракт:

1. `data/settings.json` содержит общие переносимые настройки и хранится в Git.
2. `data/settings.local.json` содержит только пути текущего компьютера и не
   хранится в Git.
3. `data/state.json` содержит диапазон и прогресс генерации и не хранится в Git.
4. `.env` содержит только API-ключи и не хранится в Git.
5. Итоговый словарь для существующих потребителей собирается централизованно;
   режимы генерации не должны знать, из какого файла пришло значение.
6. Все относительные пути приложения разрешаются от корня репозитория, а не от
   текущей папки PowerShell. Абсолютные пользовательские пути сохраняются.

Пункты первоначальной установки, отдельной команды диагностики и фиксации
версий зависимостей в эту работу не входят.

## 2. Границы активного исполнения

Активная цепочка начинается в `main.py` и использует:

- `ui/` для меню и горячих клавиш;
- `utils/settings_store.py` и `utils/coordinates_store.py` для хранения;
- `utils/generation_runner.py` для выбора обработчика;
- `utils/agent_cli.py` для `agent-plan` и `agent-run-api`;
- `sites/aistudio/` для браузерных и API-режимов;
- `utils/api_client.py` и `utils/chatgpt_parallel.py` для API.

Каталоги `config/` и `core/` являются legacy-слоем. Активный `main.py` их не
импортирует. Они используются `tests/test_suite.py`, а также совместимыми
`utils/clipboard.py` и `utils/process_manager.py`, которые не входят в текущую
цепочку запуска. `tests/conftest.py` уже изолирует legacy-хранилище от живого
`data/settings.json`.

`old_code/` не участвует в исполнении и во второй подзадаче не изменяется.

## 3. Текущее поведение и найденные места

### 3.1 Чтение и запись

- `utils/settings_store.py` использует относительный `data/settings.json`,
  дополняет файл значениями по умолчанию и при сохранении записывает весь
  объединенный словарь.
- `ui/console_menu.py` и `ui/hotkeys.py` меняют отдельные поля, но затем вызывают
  полное `save_settings()`. После введения слоев это недопустимо: так локальные
  пути, состояние и секреты снова попадут в общий файл.
- Все шесть рабочих режимов вызывают `update_start_card()` после завершения
  карточки. Функция также поднимает `END_CARD`, если новый старт оказался выше
  конца диапазона.
- Агентские команды создают копию объединенных настроек, применяют параметры
  команды только в памяти и устанавливают `SAVE_PROGRESS_TO_SETTINGS=False`.
  Это поведение нужно сохранить.
- `scripts/probe_openai_custom_size.py` обходит хранилище и напрямую читает
  `API_KEY_CHATGPT` из `data/settings.json`.

### 3.2 Зависимость от текущей папки

От текущей папки запуска сейчас зависят:

- `SETTINGS_PATH`, `COORDINATES_PATH` и `DATA_DIR`;
- проверка и чтение `PROMPTS_FILE`;
- `data/images/<side>` в браузерном и API-режиме с референсами;
- `logs/` во всех шести режимах;
- относительный `OUTPUT_BASE_DIR`;
- относительный `API_STYLE_REFERENCE_IMAGE`.

`scripts/probe_openai_custom_size.py` уже вычисляет корень через `__file__`, но
должен получать ключ через общий контракт, а не читать JSON напрямую.

### 3.3 Правила Git

Текущее правило `data/` исключает каталог целиком. Последующие отрицательные
правила для `settings_example.json` и `coordinates_example.json` не работают,
потому что сам родительский каталог не возвращен в индекс. В репозитории сейчас
нет ни одного отслеживаемого файла из `data/`.

Во второй подзадаче нужно заменить общее исключение точечными:

- хранить в Git `data/settings.json` и постоянные файлы приложения;
- исключить `data/settings.local.json`, `data/state.json` и
  `data/coordinates.json`;
- исключить временные `data/images/` и проектные файлы промптов;
- разрешить хранение постоянных `data/style_refs/`, когда такие файлы добавлены
  осознанно;
- продолжать исключать `.env`, результаты и журналы.

## 4. Классификация параметров

### 4.1 Общие настройки: `data/settings.json`

| Параметры | Назначение |
| --- | --- |
| `CURRENT_SITE`, `CURRENT_MODE`, `GENERATION_METHOD` | Выбранный режим приложения |
| `GENERATION_WAIT`, `IMAGE_WAIT_INTERVAL`, `CHECK_IMAGE_GENERATED` | Поведение браузерной генерации |
| `FACE_ASPECT_RATIO`, `BACK_ASPECT_RATIO` | Форматы сторон |
| `OUTPUT_PROJECT_NAME` | Общее имя проекта по умолчанию |
| `API_PROVIDER`, `API_PROVIDER_WITH_REFS` | Выбор провайдеров |
| `API_MODEL`, `API_MODEL_WITH_REFS`, `API_MODEL_CHATGPT` | Модели |
| `API_CHATGPT_QUALITY`, `API_IMAGE_SIZE`, `API_TIMEOUT` | Параметры запроса |
| `API_LOG_PROMPTS` | Запись промптов в журнал |
| `API_CHATGPT_PARALLEL_ENABLED`, `API_CHATGPT_RATE_LIMIT_PROFILE` | Профиль параллельности |
| `API_CHATGPT_MAX_WORKERS`, `API_CHATGPT_RATE_LIMIT_IPM`, `API_CHATGPT_RATE_LIMIT_WINDOW_SECONDS` | Рабочие ограничения Tier 3 |
| `API_CHATGPT_RATE_LIMIT_TPM`, `API_CHATGPT_MONTHLY_USAGE_LIMIT_USD` | Справочные значения Tier 3 |

Текущие значения Tier 3 `50/50/60`, `800000 TPM` и `$1000` должны перейти в
отслеживаемый файл без изменения.

### 4.2 Локальные настройки: `data/settings.local.json`

Файл имеет закрытую схему и содержит только:

```json
{
  "PROMPTS_FILE": "O:\\path\\prompts.txt",
  "OUTPUT_BASE_DIR": "O:\\path\\generated",
  "API_STYLE_REFERENCE_IMAGE": "O:\\path\\style.png"
}
```

Поля необязательны. Пустое значение `API_STYLE_REFERENCE_IMAGE` означает, что
постоянный стилевой референс не задан. Неизвестные поля считаются ошибкой
настройки, чтобы общий параметр случайно не оказался локальным.

### 4.3 Состояние: `data/state.json`

```json
{
  "START_FROM_CARD": 1,
  "END_CARD": 50
}
```

Оба поля хранятся вместе, потому что интерфейс и авто-прогресс поддерживают
инвариант `END_CARD >= START_FROM_CARD`.

### 4.4 Секреты: `.env`

| Переменная | Старое поле |
| --- | --- |
| `GOOGLE_API_KEY` | `API_KEY_NANOBANANA` и legacy `API_KEY` |
| `OPENAI_API_KEY` | `API_KEY_CHATGPT` |

Ключи не входят в `DEFAULT_SETTINGS`, общий JSON, локальный JSON или состояние.
Для совместимости итоговый словарь в памяти может содержать прежние имена
`API_KEY_NANOBANANA` и `API_KEY_CHATGPT`, но они заполняются только из среды.
Legacy `API_KEY` не должен возвращаться в сохраняемые данные.

### 4.5 Вычисляемые и временные значения

- `CARDS_TO_PROCESS` вычисляется из `START_FROM_CARD` и `END_CARD` после
  объединения слоев и нигде не сохраняется.
- `API_FACE_IMAGE_SIZE`, `API_BACK_IMAGE_SIZE` и
  `SAVE_PROGRESS_TO_SETTINGS` являются параметрами конкретного агентского
  запуска и существуют только в памяти.

## 5. Контракт загрузки и путей

Порядок приоритетов, от низшего к высшему:

1. `DEFAULT_SETTINGS` и значения состояния по умолчанию.
2. `data/settings.json`.
3. `data/settings.local.json` только для разрешенных локальных полей.
4. `data/state.json` только для `START_FROM_CARD` и `END_CARD`.
5. `GOOGLE_API_KEY` и `OPENAI_API_KEY` из процесса или корневого `.env`.
6. Параметры `agent-plan` и `agent-run-api`.

Для `.env` использовать `python-dotenv`: сначала загрузить корневой файл без
перезаписи уже заданных переменных процесса. Это сохраняет возможность задать
ключи через PowerShell и требует добавить только необходимую зависимость, без
пересмотра фиксации остальных версий.

Все пути к файлам конфигурации, координатам, `data/images`, `logs` и
`generated_images` вычисляются от `REPO_ROOT`. Для значений `PROMPTS_FILE`,
`OUTPUT_BASE_DIR` и `API_STYLE_REFERENCE_IMAGE` действует одно правило:
абсолютный путь используется без изменения, относительный разрешается от
`REPO_ROOT` перед проверкой или открытием.

Ошибочный или поврежденный необязательный локальный файл не должен незаметно
обнулять общие настройки: загрузчик возвращает понятную ошибку до запуска.
Отсутствующий локальный файл и отсутствующее состояние допустимы и заменяются
значениями предыдущих слоев.

## 6. Контракт записи

`save_settings()` нельзя сохранять как операцию записи объединенного словаря.
Хранилище должно предоставить маршрутизированные операции:

- `save_shared_settings()` записывает только белый список общих полей;
- `save_local_settings()` записывает только три локальных пути;
- `save_state()` записывает только диапазон;
- `update_start_card()` обновляет состояние и сохраняет прежний инвариант;
- `save_secret()` обновляет только соответствующую строку `.env`.

Запись JSON и `.env` выполняется атомарно через временный файл и замену. Перед
записью общего JSON секретные, локальные, вычисляемые и временные поля всегда
отбрасываются.

Маршрутизация существующих действий:

| Действия интерфейса | Назначение записи |
| --- | --- |
| Сайт, режим, метод, ожидания, проверка изображения, форматы сторон | `settings.json` |
| Провайдеры, модели, качество, размер, тайм-аут, Tier 3 | `settings.json` |
| Выбор файла промптов | `settings.local.json` |
| Стартовая и конечная карточка | `state.json` |
| Ввод ключа провайдера | `.env` |
| Авто-сдвиг после карточки | `state.json` |
| Параметры агентской команды | Только память процесса |

## 7. Миграция текущей установки

Миграция во второй подзадаче выполняется до добавления `settings.json` в индекс:

1. Прочитать текущий игнорируемый файл, не выводя значения ключей.
2. Перенести ключи в корневой `.env` под новыми именами.
3. Записать три локальных пути в `settings.local.json`.
4. Записать `START_FROM_CARD` и `END_CARD` в `state.json`.
5. Создать очищенный `settings.json` только с общими полями; Tier 3 и выбранные
   модели сохранить без изменения.
6. Проверить повторной загрузкой равенство всех несекретных эффективных
   значений и наличие обоих ключей без их печати.
7. Только после проверки изменить `.gitignore` и добавить очищенный файл в Git.

Если загрузчик встречает старые ключи в JSON, они допускаются только как
временный источник в памяти при отсутствии соответствующей переменной среды.
Любая последующая запись общего файла удаляет их. На текущем компьютере этот
запасной путь не используется после контролируемой миграции.

## 8. Расширение навыка `auto-gen-api-agent`

Во второй подзадаче в обе копии навыка добавить
`scripts/configure_local_settings.py`. Общая копия по пути, указанному
пользователем, является исходной; после проверки она синхронизируется с
`docs/skills/auto-gen-api-agent/`.

Контракт скрипта:

```text
python configure_local_settings.py
  --repo <корень репозитория>
  [--prompts-file <существующий txt>]
  [--output-base-dir <существующий каталог>]
  [--style-reference-image <существующий файл>]
  [--clear-style-reference-image]
  [--validate]
  [--dry-run]
```

Скрипт должен:

- принимать только абсолютные пути;
- проверять корень по `main.py` и `utils/settings_store.py`;
- проверять существование файла промптов, каталога вывода и непустого
  стилевого референса;
- изменять только три разрешенных поля, сохраняя остальные разрешенные поля;
- отклонять неизвестные ключи в существующем локальном файле;
- записывать UTF-8 атомарно и не читать `.env`;
- возвращать машинный JSON с `ok`, `path`, `changed`, `settings` и `errors`;
- в режиме `--dry-run` ничего не записывать;
- в режиме `--validate` только проверять текущий файл.

В `SKILL.md` нужно заменить правило, по которому `data/settings.json` является
источником ключей и локальных путей. Перед `agent-plan` навык должен запускать
проверку локального файла, а при смене рабочего проекта настраивать его через
скрипт. API-ключи скрипт навыка не меняет.

## 10. Тесты второй подзадачи

Обязательные новые сценарии:

- точный порядок объединения четырех источников и параметров команды;
- отсутствие секретов в любом записанном JSON;
- чтение `.env` без перезаписи переменной процесса;
- маршрутизация каждого изменяемого поля в правильный файл;
- сохранение инварианта диапазона при авто-прогрессе;
- отсутствие сохранения прогресса для агентского запуска;
- вычисление `CARDS_TO_PROCESS` без его записи;
- отсутствие локального файла и состояния;
- поврежденный или содержащий неизвестные поля локальный файл;
- абсолютные и относительные пути при запуске не из корня;
- миграция текущего старого формата без потери эффективных значений;
- прямой скрипт пробы больше не читает секрет из JSON;
- все режимы пишут журналы в корневой `logs/`;
- скрипт навыка: частичное обновление, очистка стиля, проверка, сухой прогон,
  отклонение относительных путей и отсутствие записи при ошибке.

Исходное состояние на 2026-07-13: `python -m pytest` завершился результатом
`117 passed, 14 warnings` за 31.71 секунды. Предупреждения относятся к возврату
значений из legacy-тестов. SHA-256 живого `data/settings.json` до и после
прогона совпал.

## 11. Критерии готовности второй подзадачи

- `git clone` получает безопасный общий `data/settings.json` без секретов.
- На каждом компьютере навык создает и проверяет только локальные пути.
- Прогресс и координаты остаются локальными.
- Запуск из любой текущей папки использует один корень приложения.
- Меню, горячие клавиши и авто-прогресс не загрязняют общий файл чужими слоями.
- Агентские команды сохраняют текущий машинный контракт и не записывают
  параметры запуска.
- Полный набор тестов проходит, а поиск по отслеживаемым файлам не находит
  реальные API-ключи.
