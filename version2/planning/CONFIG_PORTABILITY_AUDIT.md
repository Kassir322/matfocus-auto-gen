# Аудит переносимости конфигурации

Дата аудита: 2026-07-13. Уточнение контракта: 2026-07-14.

## 1. Итог

Активный v2 хранит общие настройки, секреты, локальные пути и прогресс в одном
`data/settings.json`. Файл целиком исключен из Git вместе со всем каталогом
`data/`, поэтому новый клон получает только значения из кода, а локальный файл
может незаметно переопределять обновленные значения.

После уточнения рабочего сценария второй подзадачи фиксируется минимальный
контракт:

1. `data/settings.json` содержит безопасные общие настройки и хранится в Git.
2. API-ключи не хранятся в JSON. Источники ключей: `OPENAI_API_KEY` и
   `GOOGLE_API_KEY` из окружения процесса; корневой `.env` допустим как
   удобный локальный источник и не хранится в Git.
3. `data/settings.local.json` сейчас не внедряется.
4. `data/state.json` сейчас не внедряется.
5. Для Codex/agent workflow локальные пути, диапазон, имя проекта и размеры
   всегда передаются явно через CLI-флаги.
6. Агентские запуски не должны сдвигать `START_FROM_CARD` и не должны
   записывать параметры запуска обратно в `data/settings.json`.
7. Все относительные служебные пути приложения должны вычисляться от корня
   репозитория. Пользовательские абсолютные пути в CLI остаются допустимыми.

Пункты первоначальной установки, отдельной команды диагностики, фиксации версий
зависимостей, отдельного локального JSON и отдельного state-файла в эту работу
не входят.

## 2. Границы активного исполнения

Активная цепочка начинается в `main.py` и использует:

- `ui/` для меню и горячих клавиш;
- `utils/settings_store.py` и `utils/coordinates_store.py` для хранения;
- `utils/generation_runner.py` для выбора обработчика;
- `utils/agent_cli.py` для `agent-plan` и `agent-run-api`;
- `sites/aistudio/` для браузерных и API-режимов;
- `utils/api_client.py` и `utils/chatgpt_parallel.py` для API.

Каталоги `config/` и `core/` являются legacy-слоем. Активный `main.py` их не
импортирует. Они используются `tests/test_suite.py`, а также совместимыми
`utils/clipboard.py` и `utils/process_manager.py`, которые не входят в текущую
цепочку запуска. `tests/conftest.py` уже изолирует legacy-хранилище от живого
`data/settings.json`.

`old_code/` не участвует в исполнении и во второй подзадаче не изменяется.

## 3. Текущее поведение и найденные места

### 3.1 Чтение и запись

- `utils/settings_store.py` использует относительный `data/settings.json`,
  дополняет файл значениями по умолчанию и при сохранении записывает весь
  объединенный словарь.
- `ui/console_menu.py` и `ui/hotkeys.py` меняют отдельные поля, но затем
  вызывают полное `save_settings()`. После удаления секретов из JSON это
  допустимо только для несекретных полей; ключи должны сохраняться отдельно.
- Все шесть рабочих режимов вызывают `update_start_card()` после завершения
  карточки. Для интерактивного режима это поведение пока остается в
  `data/settings.json`, потому что отдельный `state.json` сейчас не вводится.
- Агентские команды создают копию настроек, применяют параметры команды только
  в памяти и устанавливают `SAVE_PROGRESS_TO_SETTINGS=False`. Это поведение
  нужно сохранить.
- `scripts/probe_openai_custom_size.py` обходит хранилище и напрямую читает
  `API_KEY_CHATGPT` из `data/settings.json`.

### 3.2 Зависимость от текущей папки

От текущей папки запуска сейчас зависят:

- `SETTINGS_PATH`, `COORDINATES_PATH` и `DATA_DIR`;
- проверка и чтение `PROMPTS_FILE`;
- `data/images/<side>` в браузерном и API-режиме с референсами;
- `logs/` во всех шести режимах;
- относительный `OUTPUT_BASE_DIR`;
- относительный `API_STYLE_REFERENCE_IMAGE`.

`scripts/probe_openai_custom_size.py` уже вычисляет корень через `__file__`, но
должен получать ключ через общий контракт, а не читать JSON напрямую.

### 3.3 Правила Git

Текущее правило `data/` исключает каталог целиком. Последующие отрицательные
правила для `settings_example.json` и `coordinates_example.json` не работают,
потому что сам родительский каталог не возвращен в индекс. В репозитории сейчас
нет ни одного отслеживаемого файла из `data/`.

Во второй подзадаче нужно заменить общее исключение точечными:

- хранить в Git `data/settings.json` с безопасными дефолтами;
- исключить `data/coordinates.json`;
- исключить временные `data/images/` и проектные файлы промптов;
- разрешить хранение постоянных `data/style_refs/`, когда такие файлы добавлены
  осознанно;
- продолжать исключать `.env`, результаты, журналы и сгенерированные картинки.

## 4. Классификация параметров

### 4.1 Общие настройки: `data/settings.json`

| Параметры | Назначение |
| --- | --- |
| `CURRENT_SITE`, `CURRENT_MODE`, `GENERATION_METHOD` | Выбранный режим приложения |
| `GENERATION_WAIT`, `IMAGE_WAIT_INTERVAL`, `CHECK_IMAGE_GENERATED` | Поведение браузерной генерации |
| `START_FROM_CARD`, `END_CARD`, `CARDS_TO_PROCESS` | Интерактивный диапазон и совместимость текущего UI |
| `PROMPTS_FILE`, `OUTPUT_BASE_DIR`, `OUTPUT_PROJECT_NAME` | Безопасные дефолты; для Codex-запусков переопределяются CLI-флагами |
| `API_STYLE_REFERENCE_IMAGE` | Безопасный дефолт; для Codex-запусков переопределяется `--style-ref` или `--no-style-ref` |
| `FACE_ASPECT_RATIO`, `BACK_ASPECT_RATIO` | Форматы сторон |
| `API_PROVIDER`, `API_PROVIDER_WITH_REFS` | Выбор провайдеров |
| `API_MODEL`, `API_MODEL_WITH_REFS`, `API_MODEL_CHATGPT` | Модели |
| `API_CHATGPT_QUALITY`, `API_IMAGE_SIZE`, `API_TIMEOUT` | Параметры запроса |
| `API_LOG_PROMPTS` | Запись промптов в журнал |
| `API_CHATGPT_PARALLEL_ENABLED`, `API_CHATGPT_RATE_LIMIT_PROFILE` | Профиль параллельности |
| `API_CHATGPT_MAX_WORKERS`, `API_CHATGPT_RATE_LIMIT_IPM`, `API_CHATGPT_RATE_LIMIT_WINDOW_SECONDS` | Рабочие ограничения Tier 3 |
| `API_CHATGPT_RATE_LIMIT_TPM`, `API_CHATGPT_MONTHLY_USAGE_LIMIT_USD` | Справочные значения Tier 3 |

Текущие значения Tier 3 `50/50/60`, `800000 TPM` и `$1000` должны перейти в
отслеживаемый файл без изменения.

### 4.2 Секреты: окружение и `.env`

| Переменная | Старое поле |
| --- | --- |
| `GOOGLE_API_KEY` | `API_KEY_NANOBANANA` и legacy `API_KEY` |
| `OPENAI_API_KEY` | `API_KEY_CHATGPT` |

Ключи не входят в `DEFAULT_SETTINGS` и не записываются в `data/settings.json`.
Для совместимости итоговый словарь в памяти может содержать прежние имена
`API_KEY_NANOBANANA` и `API_KEY_CHATGPT`, но они заполняются только из окружения
или `.env`. Legacy `API_KEY` не должен возвращаться в сохраняемые данные.

### 4.3 Значения только для агентского запуска

Эти значения для Codex/agent workflow должны передаваться явно и существовать
только в памяти процесса:

- `--prompts`;
- `--output-base-dir`;
- `--style-ref` или `--no-style-ref`;
- `--start`;
- `--end`;
- `--project-name`;
- `--face-image-size`;
- `--back-image-size`.

`API_FACE_IMAGE_SIZE`, `API_BACK_IMAGE_SIZE` и `SAVE_PROGRESS_TO_SETTINGS`
также остаются параметрами конкретного агентского запуска.

### 4.4 Локальные и временные данные

- `data/coordinates.json` остается локальным файлом текущего компьютера и не
  хранится в Git.
- `data/images/<side>` остается временным местом для content references. Навык
  может копировать туда файлы перед запуском, потому отдельный CLI-флаг для
  content references сейчас не требуется.
- `logs/`, `generated_images/` и реальные output-каталоги остаются локальными.
- `data/settings.local.json` и `data/state.json` не планируются в ближайшем
  внедрении.

## 5. Контракт загрузки и путей

Порядок приоритетов, от низшего к высшему:

1. `DEFAULT_SETTINGS`.
2. `data/settings.json`.
3. `GOOGLE_API_KEY` и `OPENAI_API_KEY` из процесса или корневого `.env`.
4. Параметры `agent-plan` и `agent-run-api`.

Для `.env` использовать легкий загрузчик: сначала загрузить корневой файл без
перезаписи уже заданных переменных процесса. Это сохраняет возможность задать
ключи через PowerShell или системные переменные Windows.

Все пути к файлам конфигурации, координатам, `data/images`, `logs` и
`generated_images` вычисляются от `REPO_ROOT`. Для значений `PROMPTS_FILE`,
`OUTPUT_BASE_DIR` и `API_STYLE_REFERENCE_IMAGE` действует правило:
абсолютный путь используется без изменения, относительный разрешается от
`REPO_ROOT` перед проверкой или открытием.

Для агентских запусков локальные проектные пути не берутся из локального JSON:
Codex обязан передавать их через CLI-флаги.

## 6. Контракт записи

`save_settings()` больше не должен записывать секретные поля. При сохранении
`data/settings.json` секретные и временные поля отбрасываются.

Нужные операции:

- `load_settings()` собирает дефолты, `data/settings.json`, окружение и
  CLI-overrides;
- `save_settings()` сохраняет только безопасные общие поля;
- `save_secret()` не пишет JSON и либо обновляет `.env`, либо явно сообщает, что
  ключ надо задать через окружение;
- `update_start_card()` сохраняет прежнее интерактивное поведение, но агентские
  запуски продолжают работать с `SAVE_PROGRESS_TO_SETTINGS=False`.

Маршрутизация существующих действий:

| Действия интерфейса | Назначение записи |
| --- | --- |
| Сайт, режим, метод, ожидания, проверка изображения, форматы сторон | `settings.json` |
| Провайдеры, модели, качество, размер, тайм-аут, Tier 3 | `settings.json` |
| Выбор файла промптов в интерактивном меню | `settings.json` как запоминаемый дефолт |
| Стартовая и конечная карточка в интерактивном режиме | `settings.json` |
| Ввод ключа провайдера | окружение или `.env`, но не JSON |
| Авто-сдвиг после карточки | `settings.json` только вне агентского запуска |
| Параметры агентской команды | Только память процесса |

## 7. Миграция текущей установки

Миграция во второй подзадаче выполняется до добавления `settings.json` в индекс:

1. Прочитать текущий игнорируемый файл, не выводя значения ключей.
2. Перенести ключи в окружение Windows/PowerShell или корневой `.env` под
   именами `OPENAI_API_KEY` и `GOOGLE_API_KEY`.
3. Создать очищенный `settings.json` только с безопасными полями; Tier 3,
   выбранные провайдеры, модели, размеры и текущие несекретные дефолты
   сохранить без изменения.
4. Проверить повторной загрузкой равенство всех несекретных эффективных
   значений и наличие нужных ключей без их печати.
5. Изменить `.gitignore` и добавить очищенный `data/settings.json` в Git.

Если загрузчик встречает старые ключи в JSON, они допускаются только как
временный источник в памяти при отсутствии соответствующей переменной среды.
Любая последующая запись общего файла удаляет их. На текущем компьютере этот
запасной путь не используется после контролируемой миграции.

## 8. Расширение навыка `auto-gen-api-agent`

Скрипт настройки `data/settings.local.json` больше не нужен. Вместо этого в
обеих копиях навыка нужно закрепить правило:

- актуальный checkout приложения находится в `O:\git\matfocus-auto-gen`;
- Codex запускает генерацию только через `agent-plan` и `agent-run-api`;
- режим для skill-driven generation: `multiformat_with_refs`;
- локальные пути и параметры запуска всегда передаются через CLI-флаги:
  `--prompts`, `--output-base-dir`, `--style-ref`, `--start`, `--end`,
  `--project-name`, `--face-image-size`, `--back-image-size`;
- навык не полагается на `data/settings.local.json` и не создает его;
- навык не передает API-ключи в командной строке;
- перед запуском навык проверяет наличие ключей через окружение или `.env`, не
  печатая значения;
- content references продолжают копироваться в `data/images/<side>`, потому что
  отдельного CLI-флага для них нет;
- общая копия навыка по пути пользователя является исходной и после проверки
  синхронизируется с `docs/skills/auto-gen-api-agent/`.

## 10. Тесты второй подзадачи

Обязательные новые сценарии:

- приоритет окружения над пустыми или legacy JSON-ключами;
- отсутствие секретов в любом записанном JSON;
- чтение `.env` без перезаписи переменной процесса;
- сохранение безопасных общих полей в `data/settings.json`;
- отсутствие сохранения прогресса и CLI-overrides для агентского запуска;
- агентский запуск с явными `--prompts`, `--output-base-dir`, `--style-ref`,
  `--start`, `--end`, `--project-name`, `--face-image-size`,
  `--back-image-size`;
- миграция текущего старого формата без потери несекретных значений;
- прямой скрипт пробы больше не читает секрет из JSON;
- абсолютные и относительные пути при запуске не из корня;
- все режимы пишут журналы в корневой `logs/`;
- `git check-ignore` подтверждает, что `data/settings.json` отслеживаем, а
  `.env`, `data/images/`, результаты и журналы игнорируются;
- поиск по отслеживаемым файлам не находит реальные API-ключи.

Исходное состояние на 2026-07-13: `python -m pytest` завершился результатом
`117 passed, 14 warnings` за 31.71 секунды. Предупреждения относятся к возврату
значений из legacy-тестов. SHA-256 живого `data/settings.json` до и после
прогона совпал.

## 11. Критерии готовности второй подзадачи

- `git clone` получает безопасный общий `data/settings.json` без секретов.
- Для Codex/agent workflow локальные пути и диапазон всегда передаются через
  CLI-флаги.
- API-ключи берутся из `OPENAI_API_KEY` и `GOOGLE_API_KEY` или `.env`, но не
  записываются в JSON.
- Агентские команды сохраняют текущий машинный контракт и не записывают
  параметры запуска или прогресс.
- Запуск из любой текущей папки использует один корень приложения.
- Полный набор тестов проходит, а поиск по отслеживаемым файлам не находит
  реальные API-ключи.
