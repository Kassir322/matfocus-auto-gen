## AI Studio Automation v2 — ТЗ и архитектура

v2 разрабатывается в **отдельном проекте**. Код v1 копируется в папку `old_code/` для подсматривания при переносе; в v2 берём лучшее, не копируем худшее (классы ради классов, мягкая остановка и т.п.). Подробнее: [V1_TO_V2.md](V1_TO_V2.md), [ROADMAP_V2.md](ROADMAP_V2.md).

### 1. Цели новой версии

- **Упростить архитектуру**: минимум классов, максимум простых модулей и функций.
- **Чётко разделить ответственность**:
  - выбор сайта и режима;
  - разбор файлов промптов;
  - автоматизация UI для сайта (клики, ожидания, сохранения);
  - консольное управление и сводки.
- **Сделать экстренную остановку надёжной**: только жёсткий стоп подпроцесса по **Esc** (без проверки флагов внутри воркера).
- **Обеспечить масштабирование**:
  - новые режимы генерации для того же сайта (standard, multiformat, multiformat_with_refs);
  - новые сайты с собственными режимами.
- **Облегчить отладку**: структурное логирование, понятные сводки до и после запуска.

### 2. Общая структура v2 (отдельный проект)

Планируемая структура (упрощённо):

```text
<новый_проект>/
  data/                   # Настройки, координаты, файлы промптов, референсы
  old_code/               # Код v1 для подсматривания (не для запуска)
  main.py                 # Точка входа v2
  settings_store.py       # Загрузка/сохранение настроек (dict)
  coordinates_store.py    # Загрузка/сохранение координат (два словаря)
  ui/
    console_menu.py       # Текстовая "панель управления"
    hotkeys.py            # Регистрация горячих клавиш (полный набор, см. ../reference/HOTKEYS_V2.md)
  sites/
    aistudio/
      helpers.py          # Общие действия для всех режимов AI Studio
      mode_standard.py    # Стандартный режим (реализуется первым)
      mode_multiformat.py # Мультиформатный режим (лицо/оборот)
      mode_multiformat_with_refs.py  # Мультиформатный с референсами
  utils/
    window_manager.py     # Настройка рабочего окна браузера
    clipboard.py         # Буфер обмена (вставка промптов)
```

Координаты хранятся **двумя словарями**: `coordinates` (точки кликов) и `relative_movements` (смещения). В режимы передаём оба отдельно; не объединяем через `coords = {**coordinates, **relative_movements}`.

### 3. Принципы разработки v2

- **Без сложных паттернов**: никакого DI, фабрик, наследований.
- **Минимум классов**: по умолчанию используем функции и модули.
- **Одна функция — одна задача**.
- **Явные имена**: `run_multiformat_mode`, `wait_until_image_ready`, `select_aspect_ratio`.
- **Логирование**: полные логи в файл в `logs/` (имя с датой и временем запуска до секунды, см. ../reference/LOGGING.md) с тегами капсом (`[PLAN]`, `[CARD]`, `[PAIR]`, `[SIDE]`, `[OK]`, `[ERROR]`, `[SUMMARY]`), без эмодзи; в консоль — только супер основные шаги (см. ../reference/LOGGING.md).

### 4. Управление процессами

- Главный процесс:
  - показывает консольное меню;
  - даёт выбрать сайт и режим;
  - даёт выбрать файл промптов;
  - запускает подпроцесс с выбранным режимом;
  - обрабатывает Esc для экстренной остановки.
- Подпроцесс:
  - запускает выбранную функцию режима (например, `run_multiformat_mode`);
  - не знает о горячих клавишах и не проверяет флаги остановки;
  - завершение только через `Process.terminate()` из главного процесса.
- Остановка:
  - Esc в главном процессе:
    - если подпроцесс жив — `terminate()` + `join(timeout)`;
    - вывод сообщения об экстренной остановке.

### 5. Консольное управление (простая панель)

Задачи консольного интерфейса:

- Показ текущей конфигурации:
  - выбранный сайт (`CURRENT_SITE`);
  - выбранный режим (`CURRENT_MODE`);
  - путь к файлу промптов (`PROMPTS_FILE`).
- Простейшее меню:
  - **1** — выбрать сайт;
  - **2** — выбрать режим для текущего сайта;
  - **3** — выбрать файл промптов (сканирование папки `data/`, только файлы, нумерованный список — см. [SETTINGS_V2.md](../reference/SETTINGS_V2.md));
  - **4** — показать план генерации (разбор файла без кликов);
  - **5** — запустить генерацию (создать подпроцесс);
  - **0** — выход.
- Показ **сводки перед запуском**:
  - сколько карточек будет обработано;
  - сколько пар промптов (для мультиформата);
  - сколько изображений планируется сгенерировать.
- Показ **сводки после завершения**:
  - сколько изображений создано успешно;
  - сколько пропущено/сорвалось по таймауту/ошибкам.

Полный список горячих клавиш и поведение: [HOTKEYS_V2.md](../reference/HOTKEYS_V2.md).

### 6. Структура `sites/aistudio`

Цель: чётко отделить общий UI‑код AI Studio от логики конкретных режимов.

#### 6.1. `helpers.py`

Режимы передают в хелперы **два словаря**: `coordinates` (точки кликов) и `relative_movements` (смещения). Хелперы принимают то, что им нужно (например, для `save_image` нужны оба — точка IMAGE_LOCATION и смещение TO_SAVE_OPTION).

Функции низкого уровня (обёртки над `pyautogui`):

- `move_and_click(x, y, delay=0.1)` — перемещение и клик.
- `press_keys(*keys, delay=0.05)` — нажатие комбинаций клавиш.

Функции шагов UI AI Studio:

- `click_prompt_input(coordinates)` — клик по полю ввода промпта.
- `paste_prompt_text(prompt_text)` — вставка текста промпта через буфер обмена и `Ctrl+V`.
- `click_new_chat(coordinates)` — создание нового чата (кнопка «Новый чат»).
- `rename_chat(coordinates, new_name)` — переименование чата.
- `select_aspect_ratio(coordinates, ratio_text)` — выбор формата изображения (`4:3`, `3:2` и т.п.).
- `start_generation()` — запуск генерации (обычно `Ctrl+Enter`).
- `save_image(coordinates, relative_movements, file_name)` — сохранение изображения (точка IMAGE_LOCATION + смещение TO_SAVE_OPTION).

Функции для проверки генерации по скриншоту (параметры настраиваемые из settings — см. [SETTINGS_V2.md](../reference/SETTINGS_V2.md)):

- `grab_result_area(coordinates, box_size)` — скриншот области вокруг `IMAGE_LOCATION`.
- `compute_difference_score(img1, img2)` — оценка отличия двух картинок.
- `wait_until_image_ready(coordinates, timeout_seconds, check_interval, box_size, diff_threshold)` —
  ждать до таймаута ИЛИ пока область заметно изменится относительно базового скрина.
- Если настройка `CHECK_IMAGE_GENERATED` выключена — режим просто ждёт таймаут без анализа скриншота.

Все режимы (`mode_standard`, `mode_multiformat`, `mode_multiformat_with_refs`) используют только эти хелперы для кликов/ожиданий.

#### 6.2. `mode_standard.py` (реализуется первым)

- Отвечает за **старый/стандартный алгоритм генерации**.
- Внутри **нет прямых вызовов `pyautogui`**, только хелперы из `helpers.py`.
- Количество генераций на карточку **не задаётся настройкой** — определяется из файла промптов.
- Основные функции:
  - `load_tasks_from_file(path, settings) -> list[Task]`:
    - парсит файл промптов для стандартного режима;
    - возвращает список простых задач `Task` (словари с полями карточки, генерации и текста).
  - `get_plan_info(tasks) -> dict`:
    - считает количество карточек, генераций, изображений для сводки.
  - `run_mode(tasks, settings, coordinates, relative_movements)`:
    - основной цикл генерации:
      - проходит по задачам;
      - создаёт/переименовывает чаты;
      - вставляет промпты;
      - запускает генерацию;
      - ждёт `wait_until_image_ready` или таймаута (в зависимости от `CHECK_IMAGE_GENERATED`);
      - сохраняет картинки;
      - пишет структурные логи.

#### 6.3. `mode_multiformat.py`

- Отвечает за **мультиформатный режим** (лицо + оборот, разные соотношения сторон).
- Также использует только `helpers.py`.
- Соотношения сторон задаются настройками `FACE_ASPECT_RATIO` и `BACK_ASPECT_RATIO` (см. [SETTINGS_V2.md](../reference/SETTINGS_V2.md)); `BACK_ASPECT_RATIO` опционален для режимов без двух сторон карточки.
- Основные функции:
  - `load_tasks_from_file(path, settings) -> list[Task]`:
    - парсит формат `Карточка N лицо/оборот - Промпт M: текст`;
    - группирует в пары «лицо+оборот»;
    - возвращает плоский список задач с полями: `card_number`, `pair_number`, `side`, `prompt_text`, `aspect_ratio`.
  - `get_plan_info(tasks) -> dict`:
    - считает карточки, пары, ожидаемое число изображений (2 на пару).
  - `run_mode(tasks, settings, coordinates, relative_movements)`:
    - основной цикл: лицо (новый чат → промпт → имя → формат → запуск → ожидание → сохранение), затем оборот; структурное логирование по карточкам/парам/сторонам.

#### 6.4. `mode_multiformat_with_refs.py`

- Отвечает за **мультиформатный режим с референсами** (вставка изображений-референсов из `data/images/лицо` и `data/images/оборот`).
- Использует те же хелперы плюс координату `PROMPT_INPUT_AFTER_IMAGE` (поле ввода после вставки изображения).
- Алгоритм аналогичен multiformat, но с шагом вставки референса перед промптом; детали — в [INTERFACE_aistudio_modes.md](../reference/INTERFACE_aistudio_modes.md) и при переносе из v1 ([V1_TO_V2.md](V1_TO_V2.md)).

### 7. Проверка готовности изображения

- Не используем доступ к HTML/DOM — работаем только через скриншоты.
- Базовый алгоритм (если настройка `CHECK_IMAGE_GENERATED` включена):
  - перед запуском генерации снимаем **базовый скрин** области результата;
  - после запуска в цикле:
    - периодически снимаем новый скрин;
    - считаем разницу с базовым;
    - если разница выше порога — считаем, что изображение сгенерировано;
    - если время вышло — выходим по таймауту.
- Если `CHECK_IMAGE_GENERATED` выключена — режим просто ждёт таймаут (`GENERATION_WAIT` / `IMAGE_WAIT_INTERVAL` по [SETTINGS_V2.md](../reference/SETTINGS_V2.md)) без анализа скриншота (на случай плохой работы анализа).
- Параметры **настраиваемые** (из settings):
  - `timeout_seconds` — максимальное время ожидания генерации (например, `GENERATION_WAIT`);
  - `check_interval` — пауза между проверками (например, `IMAGE_WAIT_INTERVAL`);
  - `box_size` — размер области вокруг `IMAGE_LOCATION`;
  - `diff_threshold` — порог «достаточного отличия».

### 8. Горячие клавиши и поведение

Полный список и описание: [HOTKEYS_V2.md](../reference/HOTKEYS_V2.md).

- **Старт генерации**: консольное меню пункт «Запустить генерацию» или **Ctrl+Shift+S** (тот же код запуска подпроцесса).
- **Экстренная остановка**: только **Esc** (в v2 нет Ctrl+Shift+Q):
  - главный процесс проверяет, есть ли активный подпроцесс;
  - если есть — вызывает `terminate()` и короткое `join()` для завершения;
  - выводит сообщение об остановке.
- **Выход из программы**: пункт меню «0. Выход»; перед выходом гарантированно останавливаем подпроцесс, если он ещё жив.
- **Настройка координат**: **Ctrl+0** — меню выбора координаты; **Ctrl+Shift+P** — сохранить текущую позицию мыши в выбранную координату.
- **Настройка окна**: **Ctrl+Shift+V** — найти/настроить окно браузера (размер и позиция).

### 9. Что НЕ делаем в v2

- Не внедряем GUI (графический интерфейс) — только консольная панель.
- Не переиспользуем старые классы один в один — v2 проектируется проще и понятнее.
- Не реализуем мягкую остановку подпроцесса через флаги — только жёсткий стоп из главного процесса по Esc.
- Не добавляем настройку `GENERATIONS_PER_CARD` — количество генераций на карточку определяется только из файла промптов.
- Не добавляем `SAVE_FOLDER` и `LOG_ENABLED` (логирование всегда включено).
