# Интерфейсы режимов sites/aistudio (mode_standard, mode_multiformat)

Спецификация модулей `mode_standard.py` и `mode_multiformat.py`. Оба режима используют только функции из `sites.aistudio.helpers` для работы с UI; прямых вызовов `pyautogui` в режимах нет.

---

## 1. Структура Task (общее)

Задача генерации описывается словарём. Поля могут различаться между режимами.

### 1.1. Стандартный режим (mode_standard)

Формат файла промптов (пример):

```text
Карточка 1 - Промпт 1: текст первого промпта
Карточка 1 - Промпт 2: текст второго промпта
Карточка 2 - Промпт 1: текст
```

Словарь `Task` для одной генерации:

| Ключ                | Тип | Описание                              |
| ------------------- | --- | ------------------------------------- |
| `card_number`       | int | Номер карточки                        |
| `generation_number` | int | Номер генерации на карточке (1, 2, …) |
| `prompt_text`       | str | Текст промпта                         |

Дополнительные поля (имя чата, имя файла) могут вычисляться в режиме по этим полям.

### 1.2. Мультиформатный режим (mode_multiformat)

Формат файла промптов (пример):

```text
Карточка 1 лицо - Промпт 1: текст лицевой стороны
Карточка 1 оборот - Промпт 1: текст оборотной стороны
Карточка 1 лицо - Промпт 2: текст второй пары (лицо)
Карточка 1 оборот - Промпт 2: текст второй пары (оборот)
```

Словарь `Task` для одной стороны (лицо или оборот):

| Ключ           | Тип | Описание                                      |
| -------------- | --- | --------------------------------------------- |
| `card_number`  | int | Номер карточки                                |
| `pair_number`  | int | Номер пары промптов (1, 2, …)                 |
| `side`         | str | `"face"` (лицо) или `"back"` (оборот)         |
| `prompt_text`  | str | Текст промпта                                 |
| `aspect_ratio` | str | Соотношение сторон, например `"4:3"`, `"3:2"` |

Парсер должен отбрасывать неполные пары (есть только лицо или только оборот) и логировать предупреждение. В список попадают только полные пары; каждая сторона — отдельная задача в списке (порядок: лицо, оборот, лицо, оборот, … по парам и карточкам).

## 2. mode_standard.py

### 2.1. load_tasks_from_file

```python
def load_tasks_from_file(path: str) -> list[dict]
```

- **Назначение**: разобрать файл с промптами стандартного формата и вернуть список задач.
- **Аргументы**: `path` — путь к текстовому файлу (кодировка — по соглашению проекта, например UTF-8).
- **Возвращает**: список словарей `Task` (поля: `card_number`, `generation_number`, `prompt_text`). Порядок: по карточкам, внутри карточки — по номеру генерации.
- **Поведение**: построчное чтение, разбор строк вида «Карточка N - Промпт M: текст». Невалидные строки пропускаются с логированием (по желанию).
- **Ошибки**: при отсутствии файла или ошибке чтения — бросить исключение или вернуть пустой список (зафиксировать в реализации).

---

### 2.2. get_plan_info

```python
def get_plan_info(tasks: list[dict]) -> dict
```

- **Назначение**: подсчитать сводку по списку задач для вывода пользователю (план генерации).
- **Аргументы**: `tasks` — результат `load_tasks_from_file`.
- **Возвращает**: словарь с полями:
  - `cards_count` (int) — количество уникальных карточек;
  - `generations_count` (int) — общее количество генераций (= len(tasks));
  - `images_planned` (int) — планируемое число изображений (= len(tasks) в стандартном режиме).
- **Поведение**: пройти по `tasks`, посчитать уникальные `card_number`, остальное — из длины списка.

---

### 2.3. run_mode

```python
def run_mode(tasks: list[dict], coords: dict, settings: dict) -> None
```

- **Назначение**: выполнить полный цикл генерации для всех задач стандартного режима.
- **Аргументы**:
  - `tasks` — список задач от `load_tasks_from_file`;
  - `coords` — словарь координат (ключи как в `helpers`: PROMPT_INPUT, IMAGE_LOCATION, NEW_CHAT_BUTTON, CHAT_NAME_INPUT и т.д.);
  - `settings` — настройки (время ожидания генерации, путь сохранения, проверка изображения и т.п. — по соглашению проекта).
- **Поведение** (алгоритм для каждой задачи):
  1. Создать новый чат (`click_new_chat`).
  2. Клик по полю промпта (`click_prompt_input`).
  3. Вставить текст промпта (`paste_prompt_text`).
  4. Переименовать чат (`rename_chat`) — имя по задаче (например, «Карточка N - Промпт M»).
  5. Запустить генерацию (`start_generation`).
  6. Ожидать готовность изображения: `wait_until_image_ready(coords, timeout_seconds, check_interval, box_size, diff_threshold)` — параметры из `settings`.
  7. При необходимости — проверка изображения (если включена в настройках; детали в реализации).
  8. Сохранить изображение (`save_image`) с именем файла по задаче (например, `Карточка_N_генерация_M.png`).
  9. Логирование: перед задачей — `[CARD]` / номер генерации; после сохранения — `[RESULT]` успех/таймаут.
- В начале цикла вывести сводку плана (`[PLAN]`: карточки, генерации, изображений). В конце — итоговую сводку (`[SUMMARY]`: успешно, по таймауту, ошибки).
- Подпроцесс не проверяет флаги остановки; завершение только извне (`Process.terminate()`).

## 3. mode_multiformat.py

### 3.1. load_tasks_from_file

```python
def load_tasks_from_file(path: str) -> list[dict]
```

- **Назначение**: разобрать файл с промптами мультиформатного формата (лицо/оборот) и вернуть плоский список задач по сторонам.
- **Аргументы**: `path` — путь к текстовому файлу.
- **Возвращает**: список словарей `Task` с полями `card_number`, `pair_number`, `side`, `prompt_text`, `aspect_ratio`. Порядок: по карточкам, по парам, внутри пары — сначала лицо (`side="face"`, например `aspect_ratio="4:3"`), затем оборот (`side="back"`, например `aspect_ratio="3:2"`).
- **Поведение**: парсинг строк вида «Карточка N лицо|оборот - Промпт M: текст». Группировка в пары; пары без обеих сторон отбрасываются с предупреждением. Соотношения сторон задаются из настроек (например, лицо 4:3, оборот 3:2) и записываются в `aspect_ratio` каждой задачи.

---

### 3.2. get_plan_info

```python
def get_plan_info(tasks: list[dict]) -> dict
```

- **Назначение**: подсчитать сводку по списку задач мультиформатного режима.
- **Аргументы**: `tasks` — результат `load_tasks_from_file` для multiformat.
- **Возвращает**: словарь:
  - `cards_count` (int) — количество уникальных карточек;
  - `pairs_count` (int) — количество полных пар (лицо+оборот); можно вычислить как `len(tasks) // 2`;
  - `images_planned` (int) — планируемое число изображений (= len(tasks), по одному на каждую сторону).
- **Поведение**: по `tasks` посчитать уникальные `card_number`, пары и длину списка.

---

### 3.3. run_mode

```python
def run_mode(tasks: list[dict], coords: dict, settings: dict) -> None
```

- **Назначение**: выполнить полный цикл генерации для всех задач мультиформатного режима (каждая задача — одна сторона: лицо или оборот).
- **Аргументы**: те же, что у `mode_standard.run_mode`.
- **Поведение** (для каждой задачи в списке):
  - **Лицевая сторона (side == "face")**:
    1. Создать новый чат (`click_new_chat`).
    2. Клик по полю промпта (`click_prompt_input`).
    3. Вставить текст промпта (`paste_prompt_text`).
    4. Переименовать чат (например, «Карточка N - лицо - Промпт M»).
    5. Выбрать соотношение сторон (`select_aspect_ratio(coords, task["aspect_ratio"])`).
    6. Вернуться к полю промпта (`click_prompt_input`).
    7. Запустить генерацию (`start_generation`).
    8. Ожидать готовность (`wait_until_image_ready`).
    9. Сохранить изображение с именем по задаче (например, `Карточка_N_лицо_промпт_M_4x3.png`).
  - **Оборотная сторона (side == "back")**:
    - Те же шаги 1–9, с подстановкой «оборот», другого `aspect_ratio` и имени файла (например, `3x2` в имени).
- Логирование: `[CARD]`, `[PAIR]`, `[SIDE]` (карточка, пара, лицо/оборот), `[RESULT]` после каждого сохранения; в начале — план `[PLAN]`, в конце — `[SUMMARY]`.
- Координата `ASPECT_RATIO_SELECTOR` (или эквивалент) обязательна в `coords` для этого режима.
- Подпроцесс не проверяет флаги остановки.

---

## 4. Общие требования к режимам

- Импортировать и вызывать только функции из `sites.aistudio.helpers` (и при необходимости общие утилиты: логирование, буфер обмена).
- Не использовать классы для представления задач — только словари.
- Параметры ожидания генерации (`timeout_seconds`, `check_interval`, `box_size`, `diff_threshold`) брать из `settings` и передавать в `wait_until_image_ready`.
- Имена файлов и чатов формировать по единому соглашению (см. MANUAL.md текущего проекта для примеров имён).
