# Решение проблем (Troubleshooting)

Актуальные частые проблемы для текущего v2 runtime.

---

## 1. Координаты и browser-ветка

### 1.1. Координата `(0, 0)`

Симптом:

- программа сообщает об отсутствующих координатах;
- клик уходит в левый верхний угол;
- режим не стартует из-за обязательных координат.

Решение:

1. Нажмите `Ctrl+0`.
2. Выберите нужный ключ.
3. Наведите курсор на элемент.
4. Нажмите `Ctrl+Shift+P`.

### 1.2. Клик уходит не туда

Причины:

- изменилось положение окна браузера;
- изменился масштаб страницы;
- изменилось разрешение / масштаб Windows.

Решение:

1. Верните масштаб браузера к 100%.
2. Перенастройте окно через `Ctrl+Shift+V`.
3. При необходимости заново снимите координаты.

### 1.3. Не сохраняется изображение

Проверьте:

- `IMAGE_LOCATION`
- `TO_SAVE_OPTION`
- не перекрыт ли браузер другим окном

---

## 2. Окно браузера

### 2.1. `Ctrl+Shift+V` не находит окно

Причины:

- браузер не открыт;
- окно на другом рабочем столе;
- окно не похоже по заголовку на поддерживаемый браузер.

Решение:

1. Откройте Chrome / Edge / Firefox.
2. Разверните окно.
3. Повторите `Ctrl+Shift+V`.

Текущая реализация также умеет восстановить минимизированное окно, если это единственный найденный browser window.

### 2.2. Browser-старт сам создаёт окно

Это нормальное поведение.

Если `setup_automation_window()` не находит готовое окно, browser-запуск может создать новое окно браузера и настроить его автоматически.

## 3. Генерация и ожидание изображения

### 3.1. Таймаут ожидания изображения

Симптом:

- генерация идёт медленно;
- в логах появляется `[WARN] Таймаут ожидания изображения ...`

Важно:

- текущий v2 **не прерывает** шаг сохранения после такого таймаута;
- таймаут только логируется, а поток выполнения продолжает попытку сохранить изображение.

Что делать:

1. Увеличьте `GENERATION_WAIT` через `Ctrl+3`.
2. При необходимости увеличьте `IMAGE_WAIT_INTERVAL` через `Ctrl+8`.
3. Либо отключите проверку готовности через `Ctrl+4` и используйте только фиксированное ожидание.

### 3.2. Прогресс выглядит странно

Актуальный формат прогресса:

```text
Генерация X/Y из Z
```

Где:

- `X` — число успешных сохранений;
- `Y` — число уже выполненных попыток;
- `Z` — общий план.

Если `X < Y`, значит часть попыток завершилась ошибкой или пропуском.

## 4. Промпты и диапазон карточек

### 4.1. Файл промптов не подхватывается

На практике рабочий источник истины — `data/settings.json`, ключ `PROMPTS_FILE`.

Если файл не тот:

1. Откройте `data/settings.json`.
2. Проверьте `PROMPTS_FILE`.
3. Убедитесь, что путь существует.

### 4.2. Строки в файле промптов пропускаются

Теперь в browser-режимах нераспознанные строки и некоторые конфликтные случаи печатают `[WARN]` в консоль.

Проверьте формат:

- `standard`: `Карточка N - Промпт M: текст`
- `multiformat`: `Карточка N лицо|оборот Название - Промпт M: текст`

### 4.3. Карточка “сама перескочила” дальше

Это не ошибка.

После завершения последней задачи карточки runtime обновляет `START_FROM_CARD` на следующую карточку. Это сделано для продолжения с места остановки при следующем запуске.

## 5. Референсы

### 5.1. Референс не найден

Для текущего продукта это **не блокирующая** ситуация.

`multiformat_with_refs` продолжает работу без отсутствующего референса и пишет предупреждение.

Поддерживаемые имена:

- `{card_number}_{side}.png/.jpg`
- `{side}_{card_number}_{safe_card_name}.png/.jpg`

Папки:

- `data/images/лицо/`
- `data/images/оборот/`

### 5.2. Референс не вставляется

Проверьте:

- файл реально открывается;
- это PNG или JPG;
- в системе нет проблем с буфером обмена Windows.

Если вставка не удалась, режим попробует продолжить без референса.

## 6. Остановка программы

### 6.1. `Esc` не остановил генерацию

Сначала уточните, какая ветка сейчас работает.

#### Browser-воркер

`Esc` должен останавливать только browser-воркер.

Если не помогло:

1. Нажмите `Ctrl+Esc`.
2. Закройте консоль.

#### API-воркер

Это нормальное поведение: `Esc` **не останавливает** API-воркер.

Причина:

- во время API-генерации пользователь может продолжать пользоваться компьютером;
- foreground-хоткеи в этот момент специально блокируются.

Рабочий способ завершения:

1. `Ctrl+Esc`
2. или закрыть консоль

### 6.2. Хоткеи “не работают” во время API-режима

Это тоже нормальное поведение.

Во время активного API-воркера hotkeys, влияющие на foreground/UI, специально игнорируются.

## 7. Логи

### 7.1. Где искать лог

Логи лежат в папке `logs/`, имя вида:

```text
logs/auto-gen_YYYY-MM-DD_HH-MM-SS.log
```

### 7.2. Почему логов несколько

Текущая реализация browser-режимов создаёт лог-файл на запуск `run_mode()`, а не один общий лог на весь lifetime программы. Это фактическое поведение текущего v2.

## 8. Системные проблемы

### 8.1. Нет модуля `pyautogui`, `keyboard`, `pygetwindow` и т.д.

Установите зависимости:

```bash
pip install -r requirements.txt
```

### 8.2. Проблемы с буфером обмена / `win32clipboard`

Что попробовать:

1. Закрыть менеджеры буфера обмена.
2. Переустановить `pywin32`.
3. Повторить вставку вручную в AI Studio для проверки окружения.
